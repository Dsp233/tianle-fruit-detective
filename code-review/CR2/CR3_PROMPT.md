执行 AMC8 真实代码评审专项 CR3，仅修复 CR-002。仓库 https://github.com/Dsp233/tianle-fruit-detective 。本提示词在人工明确批准后执行。

先核对最新 main、CR0 Draft PR #54、CR1 Draft PR #55、CR2 Draft PR #57 及其真实 SHA。读取 CR0 的 CR-002 实验、CR2 的工作流与验收证据，从最新 main 创建独立 CR3 分支。若 CR2 尚未合并，记录其状态并独立验证依赖，不代为合并其他 PR。

CR-002 已证实：旧 `reading-quality/build.py` 从历史 BASE 取三个入口，当前 checkout 运行可成功退出但覆盖成旧阅读入口。当前 `reading-art/build.py` 在两个干净 checkout 可精确重现发布字节，现有 `--verify-release` 能识别回退。优先在旧入口加明确的写入边界，让当前发布树上误执行在写入前退出，或只允许显式隔离输出。保留重现历史构建的用途，避免将 BASE 改成 HEAD 或重新生成当前发布内容。

1. 先核查调用者、历史兼容、工作目录、输出目录和生成的三个入口。说明选择的最小改动与退出语义。
2. 在独立临时 checkout 复现旧入口成功退出并覆盖发布；用同一反例证明候选在首次写入前拒绝，或只写隔离目录。核对三入口、阅读包、插画与 release manifest 的字节以及工作树状态。
3. 两个干净 checkout 执行当前受支持的构建/校验，核对产物哈希和正式入口字节一致，并确认历史快照的显式复现途径可用。若使用隔离输出，补测目标误指发布树、父目录或符号链接的边界。
4. 复用 CR0/CR2 既有 W1、Chromium、WebKit、数据保护证据。如果候选改变发布字节或浏览器行为，先停下查明原因并保存证据。未执行的测试记为 NOT_RUN。
5. 创建独立 Draft PR，提交真实基线和候选 SHA、构建与回退对照、GitHub Actions 原始日志、剩余风险和明确的人工验收点。
