## W1 数学兼容性与发布风险判定（G5 必要门禁）

W1 是中文阅读交付，不承担数学引擎的功能升级。此前 RTM1 pending 被误判为保存失败的现象，只证明冻结 W1 预览存在，**尚未证明由 W1 引入**。原 `W1-MATH-SAVE` 的 ID 和证据/阻断历史不变，但其归属已修正为 **M（数学维护）**；名称中的 W1 仅是历史 ID，不能再被当成 W1 强制修复任务。

G5 的机器依赖从旧 `W1-MATH-SAVE` 改为 **`W1-MATH-COMPAT`（数学兼容性、归属和风险处置）**。它先用相同步骤、隔离合成数据和版本身份复核 FIX15 与原冻结 W1；只有怀疑评审 overlay 干扰或判断 QA_ONLY 时，才强制进行第三个 QA 预览环境的实际对照：

1. 正式 **FIX15**：冻结 W1 上线前的功能行为基线。
2. **W1 原冻结运行版**：无评审 overlay；确认是否新增保存失败、数据丢失或状态不一致。
3. **W1 QA 评审预览版（风险驱动）**：只在 QA 干扰被怀疑或 QA_ONLY 分类时是强制独立浏览器比较；其余情形必须用原冻结版排除 overlay 的文件身份/打包证据证明无关，不能因为 QA 私有访问困难自动 BLOCKED，也不能无证据略过。

分别记录首答/选择、草稿、pending→成功/失败时序、重复提交、刷新、重试和旧数据保护，形成可复核的浏览器操作或等效证据。三者环境必须可比，不能仅以哈希或 VM 模拟代替需要的实际浏览器验证。

**G5 判定矩阵：**

| 结论 | 实际任务归属 | W1-G5 处理 |
|---|---|---|
| FIX15 正常，原冻结 W1 异常（W1_REGRESSION） | W1 集成回归/必要的安全修复 | 修复并重新冻结候选、Chromium/WebKit 定向回归、重建 G5 哈希与清单后才能 PASS |
| FIX15 与原冻结 W1 同样异常（PRE_EXISTING） | 数学维护（历史 ID `W1-MATH-SAVE`） | 若确认不造成数据丢失/静默覆盖、风险仅 P2/P3、有可核验的风险接受记录，则 W1 兼容门禁可 PASS；不强制在 W1 完成数学维护 |
| 仅 QA 评审版异常（QA_ONLY） | Q0 评审层隔离/修复 | 原冻结运行文件不受影响且 QA 脚本已排除正式发布，经独立核验风险安全后，W1 兼容门禁可 PASS |
| 任意版本存在开放的 P0/P1、已确认数据丢失/静默覆盖，或归属尚未核实 | 发布安全问题，按实际影响归属 | **不能绕过**：保持 W1-MATH-COMPAT 未通过，必要时跨模块修复并重新冻结、执行双浏览器验收 |

`W1-MATH-COMPAT` 在 G0-X 中使用机器校验的 `disposition`：必须提供 FIX15 和原冻结 W1 两版本可比证据，以及有风险时的 QA 版证据（无风险则提供正式包排除 QA 的证明），并提供首答/草稿/pending 证据、分类及风险分级。低风险历史缺陷需具有实际责任人的风险接受记录；新增回归或重大数据风险须附修复 SHA、新工件 SHA256、双浏览器证据和更新后的 G5 清单。队列校验只检查字段完整与规则一致，**不能替代独立审核证据真实性或产生批准权限**。未确定归属不能先标 PASS。

历史 `W1-R2-INDEPENDENT` 保留 Muse 34 项清单/访问问题的 BLOCKED 事实，但**不再作为 G5 的直接机器依赖**。新的 `W1-SOFTWARE-ACCEPTANCE` 是内部软件工程门禁：实际验证阅读交互、首答/草稿、数学兼容、旧诊断和导航，绑定同源浏览器及独立工程测试证据；原 Muse 26/8 的外部验收、原始 ID 与缺证处置统一在最终 UAT，不要求 W1 阶段取得外部负责人签收。正式发布仍需适用授权。此次只改候选分支任务治理和文档，正式 main、冻结 RC、QA 预览均不变。
