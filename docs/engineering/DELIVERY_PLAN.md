## 2. G2 固定状态合同与最小安全实现

不得再开发泛化历史版本合并器。将同一数学/阅读题目区分如下状态，并对每个状态给出产品行为、数据证据和预期：

1. **已提交首答（committed）**：原始 attempt ID、首答、求助/提示和历史内容不得被后续正确答案、刷新、迁移、回退或旧页面写入悄然覆盖。读回逐字校验。
2. **已持久化但未提交的可继续草稿（persisted draft）**：刷新后能识别同题同会话并继续编辑；故障恢复后的合成数据须能通过匹配原题和版本继续，而不只是归档查看。复用 CI 42382618286 的已验证范围；对其他实际支持的交互类型按状态差异补必要测试。
3. **保存请求已开始但仍 pending 的首答/草稿**：保存状态未知时不得显示“已保存”或计为成功；在提交/离开/切换时防止静默丢弃，保留原已提交值、可重试状态和必要导出。旧页面竞争、配额、事务阻塞、异常退出仅补**受影响的必要故障矩阵**。不能依赖 Web Locks 来强制无锁旧版配合。
4. **仅内存、尚未写入的编辑状态**：关闭/杀进程后不可能凭空读回未落盘字节。必须对实际要求保留的草稿提供及时持久化、明确保存状态与关键导航保护；不能凭导出按钮声称在被杀前已导出。若无法做到原要求的保护，记录可复现 FAIL，属于发布阻断；不能新造“人工恢复即合格”的豁免。
5. **FIX15 隔离回退**：原环境导出和备份确认 → 关闭其他页面 → **全新空 profile/独立隔离环境** → 固定软件及匹配旧原文导入 → 首答/数学/学院/旧阅读逐键校验；升级后的原文另存。恢复失败或部分写入时不碰源资料，不在原真实 profile 上强行覆盖；旧无锁页面并发不被宣称安全。

判定以原始需求和 `safety-work/w1-checkpoint/w1-g2-draft-contract.md` 为依据。需产出**有限故障矩阵**及机器/人工证据，明确「已证实」「未证实」「不可保证且违反要求」；不能把所有物理层不可避免的丢失都转化为无穷开发。

## 4. 执行队列、资源纪律与决策权限

**顺序**：R0 锁定合同/清单及证据 → R1 并行收口 G1、G2（最多两条有限工作线）→ R2 合批生成最终 RC、最终 CI 与回退收据 → R3 该 RC 的独立 HTTPS 预览及 G4-E 证据 → R4 满足原合同后正式提升同一包至 GitHub Pages、G5。R3 的**预演环境准备**可在 R1/R2 同时进行，以缩短外部设备等待。

- **Work 的任务是关闭门禁和交付产物**，不是增加提交数。每轮结果必须报告：已关闭门禁数/未关闭 P0-P1 数、唯一候选 SHA、CI ID、包 SHA、预览 URL（或唯一托管阻断）、实际 iPad 版本及下一项明确工作；不输出没有实质变化的进度长文。
- **新测试准入四要素**：原始合同 ID/条款、可复现缺陷、最小修复、验收方式。无此四项不扩展范围。数据改动只补关联拼音/内容；存储变更才重跑受影响故障矩阵；仅在全部必修变更合批后重跑最后全包 CI；文档变更不触发全包 CI。
- **并发**：用户已授权单一 Work 会话作为 W1 写入者；每次检查 HEAD + expected SHA，不强推，不以无法查看其他 Work 会话为永久只读阻断，遇具体冲突才合并/暂停相应文件。
- **连续执行**：收到用户新的“继续 W1”时，Work 在本次可运行会话内完成下一项可执行工作；保存断点、等待某个 CI 完成、单次局部成功、外部 iPad 缺失都不构成停止**其余可执行任务**的理由。不承诺聊天结束后仍在后台运行，也不将额度重置理解为自动恢复。
- **停止条件**：W1 正式上线 G5 完成；或已完成所有可自动执行的必要工作，剩余仅独立人工审查、用户托管授权/真机等真实外部阻断；或确有权限、额度、真实写入冲突等客观阻断。停止时必须用具名条款、实际证据和精确 SHA 报告，不可仅写“本轮完成”。
- **发布禁令**：未关闭发布 P0/P1、原合同 G1–G4-E 未通过、冻结包与预览设备版本不一致，均**不得触碰 main、部署或宣称验收完成**。T 的长期儿童学习效果单列，不得既用它强行放行内容缺陷，也不得用它无限拖延已完成 E。
