## 2. 所有阶段适用的统一发布合同

**发布前必须完成**：代码及内容/数学答案正确性；原学习记录、首答、草稿与迁移/回滚安全；按影响范围选定的单元/定向检查，以及适用于最终运行字节的完整候选 CI、Chromium/WebKit 浏览器证据；构建源 SHA、ZIP SHA、逐文件运行清单与最终部署字节一致；没有已知未关闭的发布级 P0/P1；用户明确发布授权；上线后公网核验和故障回滚收据。

**独立浏览器验收仍保留**：Muse 能合法访问的隔离环境继续实际测试数学、阅读、交互、持久化、导航和教学内容；每项按源码/运行字节、结果及截图或日志记证据。私有预览 HTTP 403 是 BLOCKED_ACCESS，不是产品 FAIL，也不能写成浏览器 PASS。无法进入环境时报告真实阻断、可复用独立证据与风险决策；不得借真机延期省略本可做的自动化验证。

**统一延期所有真人/实机任务**：实体 iPad/手机、真实音频听感、儿童/家长真实使用、长期学习效果，全部移至 UAT，不在 W1、G0、M、W2、P 或 F 的工程/发布前置门禁中。标准状态为 `DEFERRED_BY_OWNER / NOT_RUN`。历史 Muse G4-E 报告的 `BLOCKED_DEVICE`、`BLOCKED_ACCESS`、26 核心 BLOCKED 与 8 扩展 NOT_RUN 保留事实，不重写为 PASS 或 FAIL。用户授权的是**验收时序后移**，并未证明实体设备兼容和真实语音可用；不能据此放行已知 P0/P1 或危险数据行为。

**状态区分**：模块确实上线且经公网验证后可以记 `RELEASED_PENDING_DEVICE_UAT`；最终 UAT 未完成绝不记 `FULL_UAT_PASS`。学习效果无真实观察时记 `NOT_MEASURED`。模块可按明确授权分阶段上线，但所有真机/真人工作在 F 之后统一开展。发生严重实际问题应随时触发回滚，不能以“以后才测”回避。

## 3.1 Q0 独立评审功能：验收工具先行（已批准产品需求）

**代码进展补充（2026-11-08）**：已在提交 [`cb00173`](https://github.com/Dsp233/tianle-fruit-detective/commit/cb00173b1c07bff1d115d822a13972ed0e9c7563) 入库预览专用 JS/CSS、打包脚本、两组浏览器用例和 README。两组测试基于模拟 DOM fixture；**不证明完整 W1 E2E、已部署或实际 iPad PASS**。W1-R2-QA 可以提前试装到**原有、经授权的隔离 HTTPS 预览站**，但须单独记录 QA 预览身份、原首页与变更首页 SHA、原学习程序运行文件逐项一致性；完成完整 W1 路径回归并确认不会改变首答/学习记录。原冻结 RC G4 证据仅适用于它当时的文件集合，新 QA 首页不能沿用原首页字节一致结论。私有站 403 不因安装 QA 层自动消失；同源 localStorage 的 QA 记录不可视作跨设备共享。

**定位和时机**：该功能是**应用内评审模式**，用于用户和 Muse 在正式/预览页面直接标注、导出、定位与复核问题；与「Muse 作为独立验收执行者」不是一回事。**Q0-PREVIEW 可以在 W1 G5 前的原私有预览站完成独立评审功能与浏览器验证，Q0 正式站集成仍在 G5 发布后**；可与 G0-B 非冲突部分并行。**先审实际源码、已有发布页及历史实现记录**，不得因计划列为 Q0 就认定尚未实现或重复重建；已存在的实现做定向核验、仅修确认缺口。本功能不加入冻结 W1 运行候选，不因此重跑 W1 已通过 CI，也不成为不依赖评审工具的 M 代码工作的阻断。

**用户确认的最小功能合同：**

1. 页面左下角有可切换的「评审模式」入口；启用时页面顶部显示醒目的红色模式提示，鼠标移过的目标可高亮；触控端可以选择目标元素并显示定位状态。
2. 评审模式下选择页面任意可见位置，出现意见编辑框；自动保存**页面路径、稳定元素定位、所在卡片与题目/任务标识（如适用）**、所关联版本；分类固定为「交互、视觉、内容、遗漏、Bug」，意见文本必填、提出人可空。
3. 保存后显示红色编号定位标注；点击标注可修改、标记已处理或删除。页面刷新、退出/重进评审模式、正常导航后标注仍能保留并定位到原目标；失效的元素定位必须可辨认和人工修订，不得静默错贴。
4. **评审模式点击不得触发底层跳转、提交答案、改变草稿或学习记录。** 需要翻页时先退出评审模式；重新进入后保留既有意见和编号。
5. 「评审清单」可显示、筛选及管理全部意见；支持「隐藏标注」以便无编号截图，隐藏只影响显示，不删除记录。
6. **评审清单标题/名称与导出的文件名都允许用户修改**；一键导出真实可打开的 `.md` 文件（不是仅复制摘要），逐项包含编号、分类、意见、状态、路径、元素/卡片/任务定位、版本信息及可供开发者复现的上下文，以便 Work/Codex 精准逐条修复。
7. 评审数据使用与儿童正式答题记录隔离的存储命名空间，不能覆盖原始首答/历史；不导出孩子真实答题信息或私密内容。评审任务本身无需账号体系或后台服务，除非原有实现确有既定依赖。
8. 评审应在用户授权的预览和正式页面可用，但开发/模拟记录不得污染真实学习统计。真实 iPad 上的最终触控体验仍属于项目末尾 UAT；**浏览器自动化与功能测试在 Q0 阶段必须完成**。

**Q0 独立验收的最小用例**：开启/关闭模式；悬停/选择高亮；给导航、阅读任务、数学卡片分别批注而不触发原动作；分类与可选提出人；编号、编辑/解决/删除；刷新与跨页恢复；隐藏标注后截图画面干净且记录未删除；编辑两个名称；导出并解析 Markdown、校验文件名与字段/稳定定位；验证 QA 数据绝不改变正式历史、首答、草稿。每项 PASS/FAIL/BLOCKED 需绑定真实版本及浏览器证据。若无法强制触发文件下载，必须如实记录 BLOCKED 而不是声称「支持导出」。

**阶段关闭标准**：现有实现核实 + 所有核心用例可执行且无开放 P0/P1 + 持久化/导出/数据隔离证据。发现问题按最小范围修复；Q0 通过后成为 M/W2/P/F 的通用评审核查工具，重复使用同一套合同，不在各模块再开发一遍。

## 7. G0 准入、测试与构建治理的判定规则

- P0 指已证实的原始学习数据丢失/破坏、严重错误判分或关键应用普遍不可用等发布事故。P1 指关键合同失效且没有经验证替代路径。P2/P3 为不造成上述影响的维护或体验欠项。每个严重项必须附实际路径、复现或确定性分析、影响范围、最小修复及关闭证据。
- BLOCKED_FOR_M 还必须证明问题落在 M 将修改/发布的依赖路径，且无法通过已验证隔离控制风险。仅有大文件、旧命名、工作流数量、测试重复或设计偏好不能作为阻断。已知生产 P0/P1 立即进入修复/回退，不因不影响 M 而搁置。
- 隔离后 READY_FOR_M 必须写明禁止修改的模块/存储键、允许开发范围、隔离验证及失效触发条件。跨过该边界时先关闭相关项。P2/P3 按受影响模块随改随清；不要求全仓无技术债。
- 构建输入逐个锁定版本/哈希，记录工具链和外部工件。实际入口以构建后文件反向追溯，不能只审根目录 source。先保留可用路径，再小批替换 overlay 或重复入口，并以相关语义/文件身份校验关闭；不预设重构框架。
- CI 清理先建立触发器、依赖、覆盖和发布写入矩阵。替代流程证明同等必要覆盖后才停用旧入口，保留历史证据与可定位脚本。发布任务串行且绑定目标 SHA；候选构建可取消旧任务，正在发布的任务必须可追溯地结束或恢复。
- 测试分层为文档静态检查、变更定向回归、最终候选集成、部署后核验。文档变化不触发应用全测。语义/数据/运行字节变化只重验受影响项及必要集成；相同字节、相同依赖且场景仍适用的成功证据直接继承。SKIPPED、NOT_RUN 和失败均单列。
- G2 的旧无锁页面并发和固定版隔离回退边界延续至 M/W2。软件回滚不等于数据降级；回退前保留升级后原文，旧版不能继续编辑的数据须保留并由匹配版本恢复，禁止覆盖导出或用旧 schema 强行导入。
