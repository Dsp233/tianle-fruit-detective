## 2. 所有阶段适用的统一发布合同

**发布前必须完成**：代码及内容/数学答案正确性；原学习记录、首答、草稿与迁移/回滚安全；与修改范围相符的单元、完整候选 CI、Chromium/WebKit 浏览器检查；构建源 SHA、ZIP SHA、逐文件运行清单与最终部署字节一致；没有已知未关闭的发布级 P0/P1；用户明确发布授权；上线后公网核验和故障回滚收据。

**独立浏览器验收仍保留**：Muse 能合法访问的隔离环境继续实际测试数学、阅读、交互、持久化、导航和教学内容；每项按源码/运行字节、结果及截图或日志记证据。私有预览 HTTP 403 是 BLOCKED_ACCESS，不是产品 FAIL，也不能写成浏览器 PASS。无法进入环境时报告真实阻断、可复用独立证据与风险决策；不得借真机延期省略本可做的自动化验证。

**统一延期所有真人/实机任务**：实体 iPad/手机、真实音频听感、儿童/家长真实使用、长期学习效果，全部移至 UAT，不在 W1、G0、M、W2、P 或 F 的工程/发布前置门禁中。标准状态为 `DEFERRED_BY_OWNER / NOT_RUN`。历史 Muse G4-E 报告的 `BLOCKED_DEVICE`、`BLOCKED_ACCESS`、26 核心 BLOCKED 与 8 扩展 NOT_RUN 保留事实，不重写为 PASS 或 FAIL。用户授权的是**验收时序后移**，并未证明实体设备兼容和真实语音可用；不能据此放行已知 P0/P1 或危险数据行为。

**状态区分**：模块确实上线且经公网验证后可以记 `RELEASED_PENDING_DEVICE_UAT`；最终 UAT 未完成绝不记 `FULL_UAT_PASS`。学习效果无真实观察时记 `NOT_MEASURED`。模块可按明确授权分阶段上线，但所有真机/真人工作在 F 之后统一开展。发生严重实际问题应随时触发回滚，不能以“以后才测”回避。

## 3. G0 代码治理实施合同

### G0-A：立即可做的只读审计

仓库截至本次检查 `main` 的 `.github/workflows` 有 **91 个工作流文件**，其中 83 个以 RC79 命名。这仅表示**文件存量**，并不说明它们都在运行、都是问题或都应删除。审计时重新读取实际最新 HEAD 并记录时点。

必须形成下列真实产物（可放于 `docs/engineering/governance/`），而不只是输出建议：

1. **ARCHITECTURE_AND_DEPENDENCIES.md**：实际源码入口/加载次序、数学/阅读/家长端/历史/存储/构建依赖图；指出高耦合文件和覆盖层如何影响最终运行代码。
2. **WORKFLOW_INVENTORY.csv**：逐一登记 Actions 名称、触发器、调用脚本/工件、当前有效入口、历史证据用途、建议保留/整合/归档及风险；禁止按命名推断可以删除。
3. **BUILD_RELEASE_PROVENANCE.md**：源码→构建/补丁→CI→ZIP→清单→隔离站→正式 Pages 的可追溯性；检查是否必须依赖历史 Actions 工件、非确定性 overlay、临时下载或无法复建资产。
4. **DATA_COMPATIBILITY_MATRIX.md**：FIX15/W1/M/W2 的历史原文、首答、已持久化草稿、pending、导出导入、配额、Web Locks/旧页面并发、回滚及异常退出边界；只对可实测状态宣称通过。
5. **TEST_EVIDENCE_MATRIX.md**：按 SHA、工件、场景区分模拟 DOM、Chromium/WebKit、独立浏览器、专项目标 CI 与 skipped 步骤，形成快测/定向回归/完整集成/部署后检查的层次。
6. **TECH_DEBT_BACKLOG.md**：每项 P0/P1/P2/P3 的源码/流程证据、风险、影响 M/W2 的程度、最小整改、可复用测试和关闭标准。

### G0-B：W1 发布后定向整改

按优先级依次处理：**数据完整与回滚 → 可复现的唯一受支持构建/发布路径 → 经证实的 CI 冗余/失效依赖 → 实际阻碍 M/W2 的耦合 → 长期规范**。只有证据支持的 P0/P1 且没有可靠隔离手段，才阻断进入 M；P2/P3 列入 M/W2 随改随清，不可无限拖延“完美架构”。

每次实际写入：检查最新 HEAD 与 expected SHA，单一写入者，避免覆盖 Work 并发；只修改必要文件；保留旧工作流、工件和回退可追溯性；不做新技术栈迁移、不通盘改格式、不凭文件数宣布清理成功。每个整改批次必须附变更 SHA、受影响验证、CI ID、工件清单、数据保护与回退收据。G0-B 结束给出 `READY_FOR_M` 或 `BLOCKED_FOR_M`；G0-A 审计本身不算治理完工。

## 4. 角色与执行节奏

- **Astra**：产品架构、需求定位、风险与门禁方案；不因为治理新增未批准功能。
- **Work/Codex**：G0 审计与定向整改、M/W2/P/F 工程、CI 与按授权部署；每轮提交 HEAD/证据/未关闭 P0/P1/下一动作。
- **Muse**：独立浏览器功能与教学验收；真人/设备结论只接受真实证据；缺设备不阻止其余可执行测试。
- **普通 Chat**：独立质量与发布控制，核对源码 SHA、CI、工件、部署身份及缺陷闭环。
- **用户**：批准新范围、发布、延期风险及最终 UAT。

同一工作包只有一个活跃写入者；只读审计可并行。不能把一次 Commit/CI/保存断点说成项目完成，不能承诺会话结束后自动持续执行。
