# 数学保存事务化原型（隔离，禁止直接上线）

在 FIX14 存储实现和对应应用源码副本上，将数学适配器改用已有的 `transactional`，使用存储自身的实时基线避免连续待保存时引用过期的 UI 快照，并在保存状态非 ready 时提示用户离开风险。当 Web Locks 存在时数学适配器同时持有 Web Lock 与 IndexedDB 事务，防止与仍使用 Web Lock 的旧版数学页面并发写；无新增租约/强抢。可避免升级后事务模式遗留新永久锁；不解决已经存在的旧锁。

已有永久锁没有可验证的活跃性标记：旧页面没有 Web Locks，也没有心跳；崩溃 owner 与后台活跃 owner 的锁记录不可区分。自动清除、定时强抢或仅获得 Web Lock 都无法保证旧页面不再写入；原型继续拒绝未释放旧锁。真实恢复需要在可信环境确保所有旧页面关闭并保存导出，不能声称已完成安全自动恢复。

本原型尚未核对 FIX15 实际组装输出与副本逐字一致，也未整合 W1、测试最终打包浏览器、失效旧缓存并发、事务中止时显示状态、pagehide 杀进程、iPad 或真实数据。副本中的 `progress_store.js` 将事务模式 ready 通知延后到 `tx.oncomplete`；增加的事务模拟测试覆盖 ready 顺序与 localStorage 已写而事务中止时进入只读。此变更作用于共享的阅读与数学存储，仍须最终包双浏览器和读取升级回归后才能集成。异步页隐藏导致丢失未提交内存的风险仍存在。不要依据合成测试关闭W1发布阻断。

运行：`node test_transaction_store.js`、`node test_adapter.js` 和 `node test_legacy_web_lock.js`。前者为旧事务模拟器，后者仅验证真实 `persist` 函数与受控假存储适配，不是软件验收。

混合旧版 Web Lock 的双协议测试只使用合成内存和模拟锁；老永久 owner 依然无法安全自动解除。页面隐藏期间的未保存草稿、真实 Safari/浏览器行为、语音及课程升级仍不能视为通过。
