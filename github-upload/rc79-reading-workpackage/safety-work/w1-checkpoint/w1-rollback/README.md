# FIX15 隔离恢复原型：尚未集成、不能作为 G2 通过

范围：只尝试将指定 W1 内容哈希 `d62a26aa90e5cd89a36b48db812cad91cf3bfb7bddadb2b36a71f4a59c9b2726` 回退到 FIX15 旧阅读内容哈希 `caf6da5a174e84c77412909b259c9eea972f6e72a15a0a91649d940d6eb7fcdf`，不能恢复任意版本或合并记录。

`fix15_fresh_restore.js` 的 `prepare` 在原设备只读实际阅读、数学主键和用户提供的统一导出；要求升级事件的 backupKey 与旧精确原文 SHA-256 对应，并用提供的旧数据/引擎在内存验证。随后生成含旧阅读原文、新阅读原文、数学原文和完整统一导出的归档。`restoreFresh` 仅允许空白隔离 profile、可获取该阅读锁与用户已确认隔离的情况下，先写入并回读归档，再逐项恢复旧阅读和数学主键。源 profile 不被写入。配额失败可能留下部分写入；归档必须保留，不能打开旧软件并声称恢复成功，应在新空白隔离 profile 从头恢复。旧阅读完成后不会清理任何源数据。

运行合成测试：`node w1-rollback/test_fix15_fresh_restore.js`。旧引擎 `fix15-reading-engine.js` 来源 GitHub FIX15，Git blob `4833cee12d7c90bd2c2fedafb4af844f10d6f3fb`；旧课程文件测试读取 `../restored-workpackage/safety-work/baseline/source/reading_data.js`。测试使用合成记录，覆盖旧错首答、草稿、无 digest 历史归档、W1 升级备份摘要、原值冲突、锁竞争、非空 profile、配额失败和可重入。源于自动化，不证明旧软件整包或真实设备行为。

**明确尚未完成：**

- 无浏览器页面、真实 Chromium/WebKit/iPad 验收，无已固定并验证的 FIX15 完整软件产物接入，因此不构成软件加数据完整回退。iPad 不支持 Web Locks 时入口必须拒绝，不能强制跳过锁。
- 全新隔离 profile 和关闭其他页面需要用户真实操作，JS 无法证明所有不遵守协议的旧缓存页面已关闭；该前提未满足时不得调用，不能作为同一 profile 下跨页面无竞争保证。
- 原设备内存未提交草稿与异步提交不能仅凭 storage 原文证明已保存；统一导出虽完整保存在归档内，导出是否包含所有当前草稿、保存完成时刻和读取稳定性仍需最终应用及浏览器并发测试。正式集成须明确提示并阻止未经确认的恢复；不把 `ready` 单独当成 IndexedDB `oncomplete`。
- 数学主键按字节保存并恢复，统一导出中的学院画像、未提交任务草稿、其他历史键仅原文保存在归档中，未自动写回旧软件；因此尚不能宣称所有画像、草稿恢复可用。必须在开发阶段补齐所需数据项、验证旧软件可读取、保存下载文件可靠性及失败后的操作方案。
- `oldData` 与 `oldEngine` 是注入依赖，产品集成必须将真实 FIX15 引擎和数据固定并验证其构建哈希，不能信任任意调用方伪造的引擎、存储或锁对象。内容哈希和备份摘要不是签名，不证明备份来源或防篡改真实性。
- 加入数学/阅读的逐键恢复不是跨 key 原子事务；部分写入时未回滚目标，但归档和源 profile 保留。须测试每个写入/回读失败及中断，确保绝不自动切换或报告成功。大小上限 16,000,000 个 UTF-16 单元，不足时停止并保留原件。

不得直接把此原型插入正式页面或把其中的 `ISOLATED_RECORD_RESTORED` 当成完整 G2。用户没有实体设备/声音验证时，如实标记 BLOCKED。
