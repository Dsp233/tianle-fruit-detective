# 旧诊断练习隔离方案（仅设计，尚未接入）

> 已取消，2026-11-01：遵循 `docs/engineering/DELIVERY_PLAN.md`，不实现下述独立存储/双写旁路。现采用白名单历史课程的原诊断协议，保留先修确认、未见材料、首答和辅助条件，按课程/内容版本单列报告。以下仅为历史决策记录，不能继续作为待办执行。

当前 `courseScope` 按课程过滤诊断，因而保留了旧版 13 套及历史首答，但无法从新版课程启动旧套题。直接让 `startDiagnostic` 绕过课程过滤会让旧材料看似属于新课程，并可能混入 A/B/C/D 结果；直接把旧题当普通练习写进当前阅读主记录，回退旧软件时也可能被旧统计误用。两种做法均不应采用。

可在独立工作包中实现一个明确标为“历史题库练习”的入口，并满足以下条件：

1. 家长选择具体历史套题和表单；页面显示旧版本和“练习，不是新版诊断”。历史作答从既有记录只读展示，不改写首答、原始备份、数学记录和既有画像。
2. 新练习的草稿、答案及辅助记录写入独立的、应用固定派生的历史练习键，而非现有阅读主键或数学键。它们不创建 `diagnostic_plan`，不分配 A/B/C/D，也不进入新版日程、能力、错因、周准入或诊断统计；不能把隔离键中的首次练习称为原始首次作答。
3. 展示历史原文前，须通过现有保护存储的事务化接口在阅读主记录中持久记录 `legacy_exposure`，使用已验证的历史材料 ID，并等待提交成功。当前引擎会按完全相同的正文识别跨课程已见，FIX15 旧引擎也识别同材料 ID 的该事件。保存冲突、配额失败或持久化状态不明时，先停留在未展示正文的页面并提示保留/导出；不能只在内存里记作已见。先记录已见、后进入隔离练习；中途失败最多会保守地记录一次未实际阅读，不能造成误认未见。
4. 保存、导出、导入和回退协议须明确同时处理阅读主记录与独立练习记录，不自动合并两者的首次答案。导入或跨设备来源未经验证时，不能恢复其独立性声明。完全相同正文的识别也不证明意思相近的不同正文一定未见，需要独立教学审查。

落地前至少需用合成档案，在最终打包页面的 Chromium 和 WebKit 中验证：旧数学与阅读原记录、备份和首答保留；无任何新诊断计划或条件；旧练习结果不进入当前/历史诊断统计；打开旧原文但不作答后，同文材料仍被记录为已见；刷新、跨标签页、并发写入、锁竞争、配额失败、关闭后重开、导出/导入及旧软件读取均保持保守行为。另需验证相关拼音、朗读及真实设备可用性。若无法在正文展示前确认已见事件已持久化，应保持入口关闭。
