## 同条件实测

GitHub Actions 使用 Chromium 143.0.7499.4 和本地 HTTP gzip 静态服务。每组 7 次，轮换运行顺序。首页资源稳定后注入 180 ms 延迟、160 KiB/s 带宽及 3 倍 CPU 降速。冷启动使用新浏览器上下文并禁用 HTTP 缓存。热启动点击站点标志返回首页，再在同一页面打开阅读。

从真实点击事件计到阅读首页的 `rdStart` 按钮可用。首图完成解码单独计时。入口请求计入按钮可用前下载的资源，传输量采用浏览器 Resource Timing 的 `transferSize`，含响应头。HTTP 层解压由浏览器完成，表中解压耗时只计应用调用的 pako。页面渲染耗时包含引擎初始化子阶段。

## 加载路径

原版并发上限为 3，先完成 6 个课程数据分片的下载、拼接、解压和解析，再请求 2 个脚本分片。仅调整调度时，传输量相同，首次可开始阅读从 4.491 s 降到 4.084 s。

最终候选并行请求课程数据和脚本，使用 HTTP gzip 及无损词条引用和拼音差异编码。课程数据还原后，才执行原阅读脚本并公开阅读引擎。最终候选仍一次请求整份课库，以沿用引擎对当前及历史会话、题目和草稿的完整校验。最后一份入口资源约在 2.754 s 完成，传输仍占主要时间。
